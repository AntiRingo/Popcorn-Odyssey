# 爆米花：奥德赛

原创 HTML5 爆米花经营小游戏，无构建步骤、无 JavaScript 依赖。双击 `index.html` 即可游玩。可选在线字体加载失败时会自动使用系统字体，不影响游戏。

## 游玩

1. 点击「开始营业」，每一天持续 150 秒。
2. 按住 A 工位的玉米左右摇晃，完成三段脱粒。把玉米粒碗拖入已开门的机器。
3. 将奶油罐拖入机器投料，点击门把手关门，再按机身电源开关，等待 6 秒。
4. 打开机门，点击工具架上的铲子拿起，铲子会跟随鼠标移动。点击出锅机器盛取，再点击空纸盒装入。右键或再次点击工具架上的铲子可放下。把调料罐拖到纸盒撒料，最后将纸盒拖给对应顾客收款。
5. 从左侧采购玉米、奶油、佐料，配送需要 4 秒。

机器工作时可以为下一批脱粒；已装盒时可继续爆制。每个顾客订一盒，等待超时会离开。不撒料直接拖给顾客即为原味，不消耗佐料。选定口味后不能反复调味，可以把纸盒拖进废弃桶清空重做，也可以向其他口味的顾客折价出售。

## 多存档管理

首页「新建 / 管理存档」和顶部「存档」可打开管理面板，支持创建、读取、重命名和删除。每份存档的营业天数、钱币、库存、升级与图鉴相互独立。旧版本单存档会迁移为「原有存档」，旧数据保留为备份，不会反复导入已删除档案。

「保存当前进度」会记录倒计时、顾客、配送、机器、脱粒台、纸盒和当日账本。创建或读取其他存档前，会先保存当前进度；写入失败时留在原档案。读取后在欢迎页点击继续即可恢复。满铲的食物恢复在原机器中，避免重复领取。打开管理面板期间营业暂停；结算及购买升级仍自动保存到当前档案。删除前会显示确认页面，其他档案不受影响。

存档保存在当前浏览器的本地存储中，手动保存成功后再关闭页面。可运行 `node test-saves.cjs` 和 `node test-physical.cjs` 检查存档与交互逻辑。

## 打烊升级

每日结束先阅读报纸，再进入结算与升级商店，用现有钱币购买设备。购买后立即保存，重新打开页面可返回商店。升级永久生效，可以单独购买、自由组合；调味和交付仍需要手动操作。

| 升级 | 价格 | 效果 |
| --- | --- | --- |
| 自动脱粒臂 | 65 | 每秒脱粒一次，3 秒备好一批玉米粒，备料满后停止 |
| 自动加料管 | 85 | 向空闲机器加入备好的玉米，并从库存补充奶油 |
| 自动点火器 | 100 | 原料齐全时自动启动，6 秒出锅 |
| 新增机器 | 120 / 200 / 280 | 依次购买第 2、3、4 台机器，各自独立爆制 |
| 自动采购员 | 90 | 库存不足 3 份时自动采购，优先玉米与奶油；配送中的原料不重复下单，余额不足时等待 |
| 增设脱粒工作台 | 80 / 140 / 200 | 增加第 2、3、4 个独立备料台；自动脱粒覆盖全部台面 |
| 增设包装台 | 80 / 140 / 200 | 增加第 2、3、4 个纸盒位，分别保留未调味或已调味的爆米花 |
| 自动装盒臂 | 110 | 任意机器出锅后自动装入空包装台；全部占用时等待，不覆盖成品 |

操作台中同时显示所有机器的完整外观和实时状态。单台使用大尺寸，两台并列，三至四台缩小为双列布局，不需要切换页面才能查看。每台机器都有可开合的机门和电源开关。手动投料与盛取须先开门，关门才能启动；烤制中机门锁定。自动化覆盖所有机器；缺料时停止对应步骤，补货后继续。每批依然消耗 1 玉米和 1 奶油。

脱粒台与包装台也全部同屏显示，随数量增加缩小为双列布局。每个脱粒台有玉米、案板、玉米粒和独立进度条，按住玉米来回摇晃脱粒；拖动哪一台的粒碗就从哪一台取料。每个包装台显示自己的纸盒和成品口味。拿着满铲点击目标纸盒即可装盒，再把调料罐拖到纸盒调味，再拖动纸盒交付；自动装盒自行寻找空位。满铲暂存的食物不会被自动装盒重复取用。拖错位置不扣材料，暂停、失去窗口焦点或取消触控时会放回手持物品。所有动态台面沿用保留节点的刷新方式。自动采购使用正常进货价格和 4 秒配送，费用计入进货支出。所有自动化在暂停、图鉴查阅和打烊期间停止。

## 折价交付与异变客流

正确口味按订单全价收款；错误口味按订单价格的 50% 收款，向下取整。例如辣椒订单价格 26 钱币，交付芝士爆米花可获得 13 钱币。纸盒会被交付，顾客离开，并计入完成订单和折价订单。订单卡在交付前显示实际收入；未撒料纸盒按原味交付。

异变由累计实际营业额推进，包含正确订单、折价订单和热门口味收入；进货、升级不会减少累计值。越往后需要越多营业收入，增长速度比旧版明显放缓：

| 累计营业额 | 可出现的最高形态 | 每位来客为异变顾客的概率 |
| --- | --- | --- |
| 0–799 | 普通街坊 | 0% |
| 800–2399 | 细微违和 | 12% |
| 2400–5199 | 异相显露 | 25% |
| 5200–8999 | 形态分岔 | 42% |
| 9000 及以上 | 非人来客 | 62% |

异变顾客会混合当前及较低阶段的形态，普通顾客始终可能出现。营业额下降不会降低已达到的累计阶段。游戏结算不再直接展示异变升级或门槛，通过报纸传闻暗示变化。

客流数量仍由上日营业额决定：基准间隔为 `max(2.5, 11 / (1 + 上日营业额 / 150))` 秒，带 ±15% 波动；最多 3–6 位顾客排队。

## 巷口晚报

打烊后出现次日晨刊，再进入升级商店。每期包括一则原料行情、一则热门口味报道，以及一则随累计营业额改变的巷尾耳语。

- 原料行情：一种原料批次价格上涨 25%、上涨 50% 或下降 20%，向上取整；手动与自动采购均使用实际行情价，已有库存不受影响。
- 热门口味：次日约 50% 订单为该口味，价格提高约 30%（四舍五入）；错口味按该订单新价格折半。
- 所有行情只持续报道指定的一个营业日，不叠加。次日结算重新生成报纸。
- 报纸在生成时保存；刷新或重读不会重新抽取行情。升级商店提供重读入口。

## 猎枪与袭击

操作台上方放置猎枪。新增钩指模仿者、裂喉伏客、酸冠潜客三种可能袭击的顾客；每位此类顾客入店时有 65% 概率准备一次攻击，普通顾客及其他类型不攻击。

营业期间可随时拿起猎枪，持枪图像和准星会跟随鼠标，右键可以放下。持枪时左键点击游戏页面任意位置都会射击：点中顾客按目标状态结算，点中背景、操作台或其他位置则空放，不会同时触发该位置的生产操作。每次射击后放回猎枪并装填 1.2 秒，可再次拿起；暂停和失能时不可使用。暂停、放下或射击后持枪图像会隐藏。

只有击中正在播放红色袭击预警动画的顾客才视为反击，不扣钱。射击其他任何顾客都会使其消失，并赔偿 30 钱币；包括普通顾客、和平的异变顾客，以及可能袭击但尚未动手的顾客。余额不足时扣至零。赔偿单列在每日结算中，不减少累计营业额，也不计为订单收入或进货费用。所有射击均不获得订单钱币。

袭击开始时顾客泛红、身体扑动，并显示倒计时。先点击猎枪，再点击正在攻击的顾客，在 3.2 秒窗口内反击；已提前持枪时可直接反击。成功会逼退对方。射击其他目标或空放不会取消正在发生的袭击，可在装填结束后、剩余窗口内重试。

超时则受到惊吓，4 秒内无法手动生产、交付或拿枪，营业计时和自动设备仍继续。一次只会有一位顾客进入攻击窗口，袭击结束后有冷却间隔，避免连续压制。暂停、图鉴和切到后台都会冻结攻击及失能计时；打烊清空战斗状态。

## 营业所图鉴

从顶部「图鉴」、欢迎页或打烊商店进入。营业中查阅会暂停所有计时，关闭后恢复原先的暂停状态，也可按 Esc 返回。

- 原料图鉴：玉米、奶油、焦糖、芝士、辣椒共五项，全部开放；显示原料介绍、制作用途、进货价格、库存和累计使用量。
- 客人图鉴：五个阶段各五类，共二十五份档案（含三种可能袭击的顾客）。遇见时自动收录外貌、观察描述、初见天数和累计遇见次数。未遇见的条目隐藏外貌与描述。已有档案位置的收录次数保留，内容更新为新版设计；新增第五类需要重新遇见。
- 收录进度和原料使用记录随每日结算及升级购买保存。旧存档兼容，过去未记录的客人不会自动补填，需要重新遇见。

每日结束保存天数、钱币、库存、累计完成订单、升级、上日及累计营业额、报纸行情、异变阶段、图鉴和结算报告到浏览器 localStorage。兼容旧版本存档；旧版没有累计营业额记录，只将最后一天已知营业额作为起点，之后正常累计，不推测过往收入。正在配送的货物在结算时入库，未完成食品清理。刷新页面回到已保存的报纸或升级商店；浏览器或页面地址变化、清理浏览器数据可能导致无法读取原存档。营业暂停及切换到后台均会暂停所有计时和自动化。经营困难时，若缺少基础原料且余额不足 12，总部在结算时赠送 3 份玉米与奶油。

也可在此目录运行 `python -m http.server 8080`，访问 http://localhost:8080。请固定使用同一访问方式以保留存档。

画面采用原创的暗色工业管理美术、矢量顾客与 CSS 设备插画，无引用游戏素材。

## 验证

运行 `node test-game.cjs`，检查手动生产、折价交付、进货、暂停、升级限制、四机并行与同屏标记、独立自动化、库存消耗、累计异变与混合概率、报纸行情保存与生效、袭击反击与失能恢复、图鉴解锁与暂停恢复、跨天结算和旧存档兼容。此测试使用模拟页面元素执行游戏逻辑，不替代浏览器画面与布局检查。

`node test-ui-dom.cjs` 检查定时刷新前后按钮节点和处理函数保持不变，顾客离开或机器状态变化时不替换其他点击目标。此前每 0.2 秒重新设置 `innerHTML`，可能在按下与松开之间移除按钮；现改为按标识保留节点、更新文本和属性，同时移除悬停时按钮位移。

`node test-admin.cjs` 检查独立管理页的全图鉴加载、搜索和异变阶段筛选。

## 独立配置管理页

直接打开 `admin.html`（使用本地服务器时访问 `/admin.html`）。游戏界面不设置管理页入口。目前开放只读全图鉴：五种原料、二十五份客人档案，不受遇见进度限制；支持文本搜索和异变阶段筛选。管理页与游戏共用图鉴资料和肖像绘制代码，不读取或修改游戏存档。
